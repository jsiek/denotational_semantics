\subsection{Delay and the Approximant Logical Relation}
\label{sec:approx-lr}

The proof for delay is the most difficult link in our answer to
whether a whole compiler, from a higher-order language with general
recursion down to assembly, can be proved correct with denotational
semantics (RQ1), and delay is the reason that not every pass of the
compiler can be proved correct by equational reasoning (RQ3). The
delay pass is the step of closure conversion that lowers closures to
pairs of code and environment. This section shows why its semantic
reflection resists our prior attempts and how the approximant logical
relation finally proves it.

In the source language EnvClos of delay, a closure
$\kw{clos}\;N\;\vec{M}$ is still a function: its meaning is the
meaning of its code $N$, a closed, curried function of the environment
$X$ and then the argument $Y$, applied to the tuple of the free
variables $\vec{M}$; and an application $\kw{app}\;L\;M$ means
function application:
\[
\begin{array}{rcl}
  \den{\kw{clos}\;N\;\vec{M}}\rho & = &
    \Lambda(\mlam{X} \Lambda(\mlam{Y} \den{N}(X, Y))) \;\app\; \mathcal{T}(\den{\vec{M}}\rho)\\
  \den{\kw{app}\;L\;M}\rho & = & \den{L}\rho \app \den{M}\rho
\end{array}
\]

In the target language, FlatClos, a closure is represented by a pair
of code and environment, and a call takes the pair apart. The
semantics for code is the same curried function, $\kw{pack}$ builds
the set of pairs $\pairv{u}{v}$ with $u$ from the code and $v$ from
the environment, and a call applies the first components to the second
components and then to the argument (the operator $\callop$ of Figure~\ref{fig:graph-ops}):
\[
\begin{array}{rcl}
  \den{\kw{code}\;N}\rho & = & \Lambda(\mlam{X} \Lambda(\mlam{Y} \den{N}(X, Y)))\\
  \den{\kw{pack}\;L\;M}\rho & = &
    \{\, \pairv{u}{v} \mid u \in \den{L}\rho,\; v \in \den{M}\rho \,\}\\
  \den{\kw{callc}\;L\;M}\rho & = & \den{L}\rho \callop \den{M}\rho
\end{array}
\]
Delay translates each closure into a pair and each application into a
call, and translates every other construct homomorphically:
\[
\begin{array}{rcl}
  \mathit{delay}(\kw{clos}\;N\;\vec{M}) & = &
    \kw{pack}\;(\kw{code}\;\mathit{delay}(N))\;(\kw{tuple}\;\mathit{delay}(\vec{M}))\\
  \mathit{delay}(\kw{app}\;L\;M) & = &
    \kw{callc}\;\mathit{delay}(L)\;\mathit{delay}(M)
\end{array}
\]

\paragraph{Why preservation is easy and reflection is not}
Delay changes the representation of closures, so its correctness is
not an equation. The theorem we prove is that a closed program and its
translation produce the same constants, and that one produces
something exactly when the other does. The forward half, preservation,
only requires a relation between a \emph{single} source element and a
\emph{set} of target elements, defined by recursion on the source
element (Figure~\ref{fig:preserve}); we read $v \sqsubseteq D'$ as
``$D'$ satisfies $v$''. The clause for a function entry says when a
target set satisfies it: the set must contain a closure, and calling
that closure on arguments that satisfy the entry's inputs must satisfy
the entry's output. The relation is in the style of the satisfaction relation of
Abramsky's domain logic \citep{Abramsky:1990vv,Abramsky:1993fk}, with a
source graph element in the role of the formula.
The source element is finite, so the recursion is structural, and the
proof that $v \in \den{M}\rho$ implies
$v \sqsubseteq \den{\mathit{delay}(M)}\rho'$ is a routine induction on
$M$.

The backward half, reflection, must show that every element the target
produces is accounted for by the source, and here the representation
of closures gets in the way. To see how, consider the function
$\lambda y.\, x + y$ in an environment where $x$ is $9$. In EnvClos
its meaning is a set of entries such as $[1] \mapsto 10$ and $[6]
\mapsto 15$. After delay, its code takes the environment as an extra
parameter, and the meaning of the code is a table with entries for
\emph{every} environment, such as the following two:
\[
  [9] \mapsto ([1] \mapsto 10) \qquad
  [2] \mapsto ([1] \mapsto 3)  \qquad \ldots
\]
even though the program only applies this function with the
environment $[9]$. So the target's meanings contain code--environment
combinations that correspond to no source function. Worse, a call
takes the code from $\car$ and the environment from $\cdr$
\emph{separately}, so a result may combine the code entry of one pair
with the environment of another. 

\paragraph{Relations that do not work}
We tried several natural alternatives, and each failure points to a
piece of the solution.
\begin{itemize}
\item \emph{Relating a single element to a single element} works for
  every construct except the call, because of the mixing of $\car$ and
  $\cdr$ described above.
\item \emph{Relating a possibly infinite set on both sides} handles
  the mixing, but the function case mentions the relation in both
  positive and negative positions, so the definition is not well
  founded.
\item \emph{Indexing by one target element within its whole target set}
  comes closest, but the function case must relate the entire argument
  set, which is infinite and cannot be shrunk to match the finite index.
\end{itemize}

\paragraph{The key insight}

We solve the mixing problem by relating the source not to a single
target element but to a finite \emph{list} of target elements. When a
call $D' \callop E'$ produces a result $w$, it draws on only finitely
many pairs of $D'$: one whose code contributes an entry $U_e \mapsto
(U_a \mapsto w)$, and others whose environments make up
$U_e$. Collecting these pairs into a finite list $V \subseteq D'$
gives a witness that contains both halves of the call, so the code and
the environments are matched \emph{inside} $V$, no matter which pairs
they come from. The relation then lets a call use exactly the code
entries whose environments $V$ itself provides, and ignore the junk
entries for environments that the program never supplies. The
counterpart of $V$ on the source side is a whole source denotation
$D$, which contains every entry of the source closures, so whatever
combination a call draws from $V$ is accounted for by $D$. This choice
also makes the relation well founded, as we explain below in the
paragraph on termination.

\paragraph{The approximant logical relation}

Figure~\ref{fig:alr} defines the approximant logical relation $D \ALR
V$, which relates a finite list $V$ of target elements to a source set
$D$. Its building block is the notion of a \emph{usable entry} of a
graph.  A target closure is a set of pairs $\pairv{u}{t}$ of code and
environment, and the code $u$, a curried function, has entries of the
form $U_e \mapsto (U_a \mapsto w)$: given the environment $U_e$, it
returns a function that maps the arguments $U_a$ to $w$. We write
$\entryin{U_a}{w}{V}$ when such an entry is among the codes $\car(V)$
\emph{and} the environments $U_e$ are among the environments $\cdr(V)$
that $V$ itself provides. The second condition is what makes the relation sound
in the presence of junk: a code entry for an environment that the
program never supplies, such as the entry for $x{=}2$ in the example
above, does not appear in a usable entry. Just as a call $D' \callop E'$ takes the
code from $\car(D')$ and the environment from $\cdr(D')$, the code and
the environment of a usable entry may come from different pairs of $V$.

A \emph{batch of calls} $\callsto{V}{U}{W}$ then says two things.  The
second conjunct says that each result $w$ in $W$ is produced by a
usable entry of $V$ whose arguments are among $U$. The first conjunct,
$U \subseteq \mathsf{args}(V)$, says that $U$ contains only arguments
that some usable entry of $V$ take, so the arguments are shallower
than $V$, which the recursion needs.

One layer ${\trianglerighteq^{Q}}$ of the relation has four clauses:
\begin{enumerate}
  \item the constants of $V$ are in $D$;
  \item if $V$ is nonempty, so is $D$;
  \item every batch of calls to $V$ on argument $U$ related to $E$
    produces a $W$ related to $D \app E$; and
  \item every projection of $V$ is related to the same projection of $D$.
\end{enumerate}
The third clause is where the $\car$ and $\cdr$ of the call operator
meet: through usable entries, the code comes from $\car(V)$ and the
environments from $\cdr(V)$, both within the finite list $V$.

\paragraph{Termination}

The definition of the approximant logical relation $D \ALR V$ is by
recursion on the depth of $V$. The relation occurs at the arguments of
a call, in negative position, which is what made the relation between
two infinite sets ill founded. Here every recursive occurrence is at a
list shallower than $V$. The arguments $U$ are shallower than $V$
because the first conjunct of a batch of calls requires
$U \subseteq \mathsf{args}(V)$; without that conjunct, $U$ could
contain elements deeper than $V$. The results $W$ are shallower than
$V$ because each of them is the output of an entry in $V$. Finally,
the projections of $V$ are shallower than $V$ because they consist of
components of the elements of $V$. The index $k$ of ${\ALR_k}$ is only a termination device:
any index that bounds the depth of $V$ gives the same relation
(Lemma~\ref{lem:depth-irrelevant}), so we may fold and unfold ${\ALR}$
as if it satisfied ${\ALR} = {\trianglerighteq^{\trianglerighteq}}$
directly.  The tower $\ALR_0, \ALR_1, \ldots$ has the same shape as
the one \citet{Reynolds:1974aa} used to relate the direct and
continuation semantics of a language, which he built stage by stage
along the inverse-limit construction of its domains
\citep{Scott:1971aa,Smyth:1982aa}. His index ranges over the stages of
both domains and his relation is the intersection over all of them;
ours bounds the depth of the finite target side only, and depth
irrelevance makes an intersection unnecessary.

\begin{lemma}[Depth irrelevance]\label{lem:depth-irrelevant}
If every element in $V$ has depth less than $k$ and less than $j$, then
$D \ALR_k V$ if and only if $D \ALR_j V$.
\end{lemma}

The relation is also monotone in $D$ and antitone in $V$: a larger
source set and a sublist of the target list preserve it.

\paragraph{Why not recursion on types}
The intermediate languages are typed, so one might hope to define the
relation by recursion on types, as \citet{Chlipala:2007fk} and
\citet{Nielsen:2000aa} do. Recursive types rule this out. The meaning of
$\kw{fold}$ and $\kw{unfold}$ is the identity, so the relation at
$\mu X.\,A$ would have to be the relation at $A[\mu X.\,A/X]$, which is
not smaller; at $\mu X.\,X \rightarrow \mathrm{Int}$, the application
clause asks for the relation at the argument type, which is
$\mu X.\,X \rightarrow \mathrm{Int}$ itself. The depth of the finite
approximation, by contrast, decreases at every call, and the elements of
the graph model are untyped, so the depth needs no help from the types.

\paragraph{The fundamental lemma}
Environments $\rho$ and $\rho'$ are related when, for every variable
$x$ and every finite $V \subseteq \rho'(x)$, we have
$\rho(x) \ALR V$, together with the consistency and nonemptiness
that the graph model requires of environments.

\begin{lemma}[Fundamental lemma]\label{lem:delay-fundamental}
If $\rho$ and $\rho'$ are related, then for every term $M$ of EnvClos and
every finite $V \subseteq \den{\mathit{delay}(M)}\rho'$, we have
$\den{M}\rho \ALR V$.
\end{lemma}

The proof is by induction on $M$. Two cases carry the weight. For a
call, a finite $V \subseteq D' \callop E'$ is produced by finitely many
pairs and arguments, by continuity of the graph model: there are finite
$W \subseteq D'$ and $U \subseteq E'$ with $\callsto{W}{U}{V}$. The
induction hypotheses give $\den{L}\rho \ALR W$ and
$\den{M}\rho \ALR U$, and clause~3 of the first, applied to this batch
of calls, gives $\den{L}\rho \app \den{M}\rho \ALR V$. For a closure,
we must establish clause~3 for the set of pairs
$\den{\kw{pack}\;(\kw{code}\;N')\;(\kw{tuple}\;\vec{M}')}\rho'$: an
entry of a batch of calls has environment inputs $U_e$ drawn
from the environments that the list itself provides, which are
approximations of the tuple of free variables, so the induction
hypothesis for $\vec{M}$ relates them to the source environment, and
the induction hypothesis for the body $N$ relates the results. This is
where the condition $U_e \subseteq \cdr(V)$ in the definition
of a batch of calls earns its keep: it is exactly what excludes the code
entries for environments that the program never supplies.

\begin{theorem}[Correctness of delay]\label{thm:delay}
For a closed term $M$ of EnvClos and a constant $c$,
$c \in \den{M}$ if and only if $c \in \den{\mathit{delay}(M)}$, and
$\den{M}$ is nonempty if and only if $\den{\mathit{delay}(M)}$ is.
\end{theorem}

Reflection follows from Lemma~\ref{lem:delay-fundamental} with the
empty environments: a constant $c$ of the target is the one-element
list $[c]$, and clauses 1 and 2 give $c \in \den{M}$ and the
nonemptiness of $\den{M}$. Preservation follows from the single-element
relation $\sqsubseteq$.

\paragraph{The cost}
Delay is the most expensive pass of the denotational proof: 524 lines
of Agda, against 35 to 139 for the same pass in the three operational
styles (Section~\ref{sec:evaluation}). Most of the difference has three
sources. First, the denotational proof needs two directions, while a
simulation proof gets the backward direction for free from forward
simulation and the determinism of the target. The graph model has an
analogue of determinism, the consistency of denotations, and it does
part of the job: if the source produces a constant, the forward
direction puts that constant in the target, and consistency rules out
any other. But the graph model represents divergence as the empty set,
the absence of evidence, and a forward relation cannot carry absence.
Showing that a diverging program compiles to a diverging program is
therefore a separate argument, and that argument is reflection. (We use
different relations for the two directions, the structural one for
preservation and the approximant one for reflection, because a single
relation parameterized by the direction made the proof longer: on an
earlier version of the compiler, switching from one relation to two cut
the proof of delay from 1,358 to 832 lines.)
Second, reflection needs the finite lists, the batches of calls, and
the lemma that extracts them from a target call. Third, $\beta$-rules in
the graph model hold only under side conditions of nonemptiness and
continuity, which a machine gets for free by taking a step. We return
to these numbers in Section~\ref{sec:evaluation}.
