\section{Introduction}
\label{sec:intro}


Denotational semantics offers a crisp recipe for compiler correctness:
the meaning of a program is a mathematical object, a compiler pass is
correct when the meaning of a program before the pass equals its
meaning afterward, and the proof is by equational reasoning.  This
recipe was used in early denotational proofs of compiler correctness
\citep{Polak:1981aa,Clinger:1984aa}, but becomes difficult when
compilation changes the representation of program values. For example,
compiling lexically scoped functions to a first-order target language,
such as assembly, requires \emph{closure conversion}, which replaces
each function with a pair of a code pointer and the values of its free
variables, and replaces each call with code that takes the pair apart
and jumps to the code pointer. It therefore turns functions into data,
and a correctness proof must relate the two different representations.

A correct compiler must both preserve the behavior of the source
program and reflect the behavior of the generated target program. To
be precise, \emph{semantic preservation} says that if the source
program produces output, the target program produces the same output;
\emph{semantic reflection} says that if the target program produces
output, the source programs produces the same output. By
contraposition, reflection guarantees that a diverging source program
compiles to a diverging target program.  Establishing semantic
reflection denotationally for closure conversion is the hard part.
After closure conversion, the meaning of a function's code describes
its behavior on every environment, not just the environment with which
the compiled program pairs it. The target denotation therefore
contains code--environment combinations that correspond to no source
function, and a reflection proof must show that these combinations
never contribute an answer.

These challenges motivate five research questions:
\begin{description}
\item[RQ1] Is it possible to prove correctness of a whole compiler
  using denotational semantics, i.e., from a higher-order language
  with general recursion down to a typed assembly language?
\item[RQ2] Does the compositionality and equational reasoning afforded
  by denotational semantics yield concise correctness proofs for some
  compiler passes?
\item[RQ3] Can equational reasoning prove all the passes of the whole
  compiler correct?
\item[RQ4] How do denotational approaches compare overall with
  operational approaches to proving correctness of a whole compiler?
\item[RQ5] Does the choice of denotatonal model (Scott domains or
  graph model) affect the proof?
\end{description}

We answer RQ1 affirmatively, in two denotational models. The missing
link was a denotational proof that closure conversion both preserves
and reflects divergence for a higher-order language with general
recursion, and we give such a proof for both models. Our first model
is a graph model, in which a program's denotation is a set of
inductively defined \emph{graph elements}. Each element is a finite
piece of evidence about the program's behavior, the meaning of a
function is a set of input--output entries, and a program that
diverges produces no evidence, so its meaning is the empty set
\citep{Engeler:1981aa,Plotkin:1993ab,Scott:1976lq}. The reflection
direction uses a new kind of relation between denotations, which we
call an \emph{approximant logical relation}.  Our key insight is to
relate a finite set of target graph elements (a finite approximation)
to a possibly infinite source denotation, and define the relation by
recursion on the depth of the elements in the finite set
(Section~\ref{sec:approx-lr}). Our second model uses Scott domains, in
which a program denotes an element of a standard universal domain of
tagged values and divergence is the least element. There we define the
relation by recursion on the stages of the bilimit that constructs the
domain, as \citet{Reynolds:1974aa} did to relate direct and
continuation semantics. At each stage, the relation relates an
approximation of one value to the whole other value
(Section~\ref{sec:scott-delay}).

We use these denotational closure-conversion results in two
correctness proofs of a ten-pass compiler from a call-by-value
$\lambda$-calculus with iso-recursive types, which we call \iswim, to
a typed assembly language.  Recursive types let us write the
call-by-value fixed-point combinator, so \iswim\ has general recursion
and admits divergence. The compiler first applies a source-to-source
optimizer modeled on the cp0 pass of Chez Scheme
\citep{Waddell:1997fk}, then performs closure conversion in four
passes, and finally uses five passes to make functions global, remove
complex operands, lift locals, make control flow explicit, and select
instructions. Every language in the compiler has a denotational
semantics in each model. In both, we prove most passes correct by an
equation between the denotations before and after the pass. RQ3
nevertheless has a negative answer. The pass that lowers closures to
code and environment pairs, which we call \pass{delay}, does not yield
to equational reasoning; its reflection proof uses the approximant
logical relation in the graph model and the stage relation in Scott
domains.

The whole-compiler correctness theorem states that the source and
target denotations contain the same constants and are nonempty
together. We also prove that the denotational semantics of \iswim\ and
of the assembly language are adequate with respect to the interpreters
for those languages. Our correctness theorem is therefore equivalent
to the usual operational one.  We mechanize all of these results in
Agda.

The closest prior denotational proofs each stop short of this
combination of closure conversion, general recursion, and semantic
reflection. \citet{Chlipala:2007fk} proved correct a compiler from the
simply typed $\lambda$-calculus to assembly, including closure
conversion.  However, the simply typed $\lambda$-calculus has no recursion, so every program terminates and there is no
divergence to preserve. For a language with recursive
functions, \citet{Nielsen:2000aa} used a domain-theoretic semantics to
prove that defunctionalization, a close cousin of closure conversion,
preserves the meaning of terminating programs. His type-indexed
relation and fixed-point induction establish semantic preservation but
say nothing in the other direction. Nielsen leaves that direction for
later: ``Eventually, we want to prove full correctness, i.e., semantic
equivalence of the two programs.''
\citet{Banerjee:2001aa} proved both directions, but gave an operational
semantics to the source language and a denotational semantics only to
the first-order target. They report that they ``know of no other proofs
of correctness (that is, both directions) for ordinary or CFA-based
defunctionalization in the presence of recursion.''

Other denotational compiler proofs for source languages that admit
divergence avoid closure conversion. Some of those proofs are about
compilers for first-order languages. \citet{Polak:1981aa} considers a
subset of Pascal, \citet{Xia:2019aa} use interaction trees for a
compiler from an imperative language to assembly, and
\citet{Cheng:2026aa} use sets of behaviors for the front end of
CompCert. Other proofs are about compilers whose target languages
support closures directly, such as those of \citet{Clinger:1984aa}
and \citet{Benton:2009aa}.

On the operational side, there are many proofs of compiler correctness
that handle closure conversion in languages with general
recursion. The proof techniques they use include
simulations~\citep{Wand:1994aa,Dargaye:2009aa}, relations on values
and states~\citep{Kumar:2014aa}, and step-indexed logical
relations~\citep{Hur:2011aa}. When \citet{Chlipala:2010aa} proved
correctness of a compiler for a language with recursion, he switched
to operational semantics, explaining that the denotational approach of
his 2007 compiler ``cannot be applied directly to Turing-complete
programming languages.'' We know of no prior denotational proof of
closure conversion for a language with general recursion that both
preserves and reflects divergence.

Finally, to answer RQ2, RQ4, and RQ5, we compare the sizes of the two
denotational proofs with each other and with three operational proofs
of the same compiler: with abstract machines and simulations; with
clocked interpreters and value relations; and with standard reduction
semantics and simulations. Each of the five developments covers the
ten-pass pipeline and proves an analogous correctness property in its
own semantics. Earlier comparisons of semantic styles for compiler
proofs cover a single phase or pass \citep{Owens:2016aa,Kahn:2025aa};
ours is, to our knowledge, the first on a compiler for a higher-order
language down to assembly.

The comparison answers RQ2 affirmatively and explains, pass by pass,
the mixed answer to RQ4. Where a pass keeps the representation of
values, equational reasoning is concise. For example, the proofs of the source
optimizer, \pass{simplify}, take 349 lines in the graph model and 411
with Scott domains, against 508 to 697 for the operational proofs
(Section~\ref{sec:equational}). Where a pass changes the representation
of closures, the relation between denotations makes the proof larger,
which quantifies the negative answer to RQ3: the proofs of
\pass{delay} take 450 and 723 lines against 35 to 126. The two effects nearly cancel. Counting each proof against its own semantics, the graph-model
development ranks second of the five, behind clocked interpreters, and
the Scott-domain development fourth, ahead of reduction semantics;
once the language-independent infrastructure is counted, they rank
third and fifth.  For RQ5, the Scott-domain proof is 1.4
times as large as the graph-model proof and larger for every pass. Much
of the difference is in \pass{delay}, where we must show that the stage
relation is admissible and preserved by the maps between stages, and
where the method of
\citet{Pitts:1996aa}, which would avoid the stages, does not apply
directly (Section~\ref{sec:evaluation}).
