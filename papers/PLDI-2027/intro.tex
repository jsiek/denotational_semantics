Proving a compiler correct is one of the oldest applications of formal
semantics. \citet{McCarthyPainter67} proved correct a compiler for
arithmetic expressions in 1967, and \citet{MilnerWeyhrauch72} proved
correct a compiler for a simple imperative
language, in Scott's logic of
computable functions, five years later. In the 1970s, the denotational
semantics of Scott and Strachey offered an especially clean foundation
for such proofs. The meaning of a program is a mathematical object, so a
compiler pass is correct when the meaning of a program before the pass
equals its meaning afterward, and the proof is equational reasoning.
\citet{Polak81} used this recipe on a compiler for a subset of Pascal,
\citet{Clinger84} used the same recipe to prove correct a compiler for
Scheme, and
Guttman, Ramsdell, and Wand \citeyearpar{VLISP95} carried the recipe into VLISP, a verified implementation of Scheme that went down to byte code.
However, in each of these compilers either the source language lacks
first-class, lexically scoped functions, or the target language supports
such functions directly.

Compiling a language with first-class, lexically scoped functions to a
first-order target language, such as assembly, requires a pass called
\emph{closure conversion}. A function that mentions variables from its
enclosing scope is represented at run time by a \emph{closure}, code
bundled with the values of its free variables, but a first-order target
language has nothing of the sort. Closure
conversion therefore replaces each closure with an ordinary pair of a
code pointer and an environment, and each call with a step that takes
the code and the environment out of the pair and jumps to the code, so
that the rest of the compiler never sees a function value. Closure conversion is the
step that turns functions into data, so a correctness proof for closure
conversion must relate two very different views of what a function is.

Denotational proofs of closure conversion have run into the same
obstacle again and again: divergence. A correct compiler must neither
lose a program's answers nor invent new ones, and in particular a compiler must
compile a diverging program to a diverging program. A correctness
theorem therefore has two halves. \emph{Preservation} says that whatever
the source program computes, the compiled program computes.
\emph{Reflection} says the converse: whatever the compiled program
computes, the source program computes, so a program that diverges is not
compiled into one that terminates. Preservation is the easy half;
reflection is the hard one. After closure conversion, the meaning of a
function's code describes its behavior on every environment, not just
on the environment that the compiled program pairs it with, so the
meanings of target programs contain code--environment pairs that
correspond to no source function, and a proof of reflection must show
that these pairs never contribute an answer. \citet{Chlipala07} built, in Coq, a compiler from the simply
typed $\lambda$-calculus to assembly language with a denotational
semantics for every intermediate language, including the target of
closure conversion. Chlipala observed that the target denotations ``allow more
behavior'' than the source and sidestepped the problem with types, an approach that works because
Chlipala's source language has no recursion: every program
terminates, and its denotation is an ordinary Coq function.

With recursion, the denotational attempts stop short. \citet{Nielsen00}
gave a denotational proof, using domain-theoretic semantics for both
languages, that defunctionalization, a close cousin of closure
conversion, preserves the meaning of programs in a simply typed language
with recursive functions. Nielsen's relation is indexed by types and relates a
diverging source program to every target program, which lets a
fixed-point induction prove that terminating programs keep their meaning
but says nothing in the other direction. Nielsen leaves that direction
for later: ``Eventually, we want to prove full correctness, i.e.,
semantic equivalence of the two programs.'' \citet{BHR01} gave the
complete proof, but with an operational semantics for the source
language and a denotational one only for the first-order target, and
Banerjee, Heintze, and Riecke report that they ``know of no other proofs of correctness (that is,
both directions) for ordinary or CFA-based defunctionalization in the
presence of recursion.''

Operational semantics, meanwhile, carried the day.
\citet{PottierGauthier06} proved that untyped defunctionalization
preserves both convergence and divergence by a simulation between
operational configurations. When \citet{Chlipala10} next built a
compiler for an untyped language with general recursion, Chlipala switched to operational semantics, explaining that the approach
of his 2007 compiler ``cannot be applied directly to Turing-complete programming languages.'' The state-of-the-art
verified compilers for higher-order languages are operational: CakeML
\citep{CakeML14} proves its closure conversion with a clocked functional
big-step semantics, and CertiCoq \citep{CertiCoq19}
proves the same pass correct with step-indexed logical relations. CompCert \citep{Leroy09}, whose source
language is first-order, set the standard for the simulation proofs that most of these
compilers follow. The denotational proofs that do cover
divergence avoid closure conversion: some have first-order source
languages, such as the interaction trees of \citet{XiaITrees20} and the
compositional verification of \citet{Cheng26}, and others, such as the
proof of \citet{BentonHur09}, compile to a machine in which closures
remain primitive values. We know of no denotational proof of closure
conversion for a language with general recursion that both preserves
and reflects divergence.

This paper gives such a proof. We prove correct a compiler from a
call-by-value $\lambda$-calculus with iso-recursive types, which we call
\iswim, through closure conversion, to a typed assembly language, and
we check every step in Agda. Recursive types let us write the call-by-value fixed-point
combinator, so \iswim\ has general recursion and admits divergence. The
compiler has ten passes: a source-level simplifier, four passes that
implement closure conversion, and five that bring the program down to
assembly (making functions global, removing complex operands, lifting
locals, making control flow explicit, and selecting instructions).  Every
language in the compiler, from \iswim\ to assembly, has a denotational
semantics, and the correctness theorem is that the source program and
the compiled program stop with the same constant, or both diverge.

The denotational semantics we use is a graph model, in the tradition of
\citet{Plotkin93}, \citet{Scott76} and \citet{Engeler81}. The meaning of
a program is a set of finite pieces of evidence about its behavior. The
meaning of a function is a set of tables, each table a finite list of
input--output entries, and the meaning of an application collects the
outputs of the tables whose inputs are covered by the meaning of the
argument. A program that diverges has no evidence to offer, so its
meaning is the empty set. The model is
elementary, needing only sets and inductive definitions, and the model
was used by Siek \citeyearpar{Siek17} to prove adequacy and the correctness of a function inliner.

Most passes of our compiler are proved by an equation between the
meanings of a program before and after the pass, one language construct
at a time. The exception is the pass that lowers closures into code and
environment pairs, which we call \emph{delay}. The preservation half of
the proof for delay is a structural induction, but the reflection half
resisted every relation we and others
tried. Relating one target value to one source value fails because the
target takes the code and the environment of a closure apart, so no
single source value corresponds to a single target value. Relating whole
sets on both sides makes the definition recursive in negative positions.
Step-indexed relations tame such definitions by counting steps of
evaluation, but a denotational semantics has no steps to count.
Indexing by the depth of a value, in the style of Pitts's projections,
fails because a small output of a function can depend on an arbitrarily
deep input.

The key insight is that only one side of the relation needs to shrink. Instead of relating two
infinite sets, we relate a finite set of target observations to an
arbitrary source denotation, and we define the relation by recursion on
the depth of the finite set. We call the result an \emph{approximant
logical relation}. The depth of the finite approximation bounds the
recursion, so the definition is well founded without steps, without
types, and without any restriction on the source side. Types cannot
replace this index: with recursive types, the application case of a
function of type $\mu X.\,X \Rightarrow \mathrm{Int}$ returns to the
same type, so a relation indexed by type does not decrease. The
approximant logical relation is, to our knowledge, the first relation
between two denotational semantics that is indexed by a finite
approximation of one of the two denotations.

A denotational correctness theorem is a statement about meanings, and a
reader may reasonably ask what the theorem says about running programs. We
therefore prove that the graph-model semantics of \iswim\ and of the
assembly language are adequate with respect to interpreters for those
languages. Together with the compiler theorem, adequacy gives the
end-to-end statement that a source program and its compiled assembly
program stop with the same constant or both diverge, which is the same
statement that proofs based on operational semantics make.

Does the denotational approach pay for itself? To find out, we proved
the same compiler correct three more times, using the operational
styles behind the best-known verified compilers: abstract machines with
simulations, as in CompCert; clocked interpreters with value relations,
as in CakeML; and reduction semantics with simulations. We held all four
proofs to the same accounting rules and the same end-to-end theorem.
Comparisons of semantic styles for compiler proofs exist, but at a
smaller scale. \citet{Owens16} found that proving one compiler phase
correct took 43 lines against a relational big-step semantics and 18
lines against a functional one, and \citet{Kahn25} compared three
operational semantics by the lines of Agda needed to prove one
compilation to a Krivine machine correct. Our comparison is, to our knowledge, the first on a whole compiler down to assembly that includes a
denotational style.

The denotational proof comes to 1,958 lines of Agda. The denotational
proof is smaller than the proofs using abstract machines (2,258 lines) and reduction
semantics (3,207 lines) and larger than the proof using clocked
interpreters (1,653 lines), but the total hides the more interesting
story. Where a pass leaves program values at the same level of
abstraction, equational reasoning wins: the denotational proof for the
simplifier takes 360 lines against 584 to 715 for the others. Where a
pass changes how closures are represented, the denotational proof loses:
delay takes 524 lines against 35 to 139.
