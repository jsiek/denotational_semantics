\section{Introduction}
\label{sec:intro}


Denotational semantics offers an account of compiler
correctness: the meaning of a program is a mathematical object, so a
compiler pass is correct when the meaning of a program before the pass
equals its meaning afterward, and the proof is equational reasoning.
This recipe guided early denotational proofs of compiler correctness
\citep{Polak:1981aa,Clinger:1984aa}, but becomes difficult when
compilation changes the representation of program values. For example, compiling first-class, lexically scoped functions to a first-order target language, such as assembly, requires \emph{closure conversion}, which replaces each function with a
pair of a code pointer and the values of its free variables, and
replaces each call with code that takes the pair apart and jumps to
the code pointer. It therefore turns functions into data, and a
correctness proof must relate two different views of what a function
is.

A correct compiler must keep every answer of the source program and
produce only those answers. \emph{Semantic preservation} says that whatever the source
program computes, the compiled program computes; \emph{semantic
reflection} says the converse. By contraposition, reflection
guarantees that a diverging source program compiles to a diverging
target program.  Establishing this guarantee denotationally for
closure conversion is the hard part.  After closure conversion, the
meaning of a function's code describes its behavior on every
environment, not just the environment with which the compiled program
pairs it. The target denotation therefore contains code--environment
combinations that correspond to no source function, and a reflection
proof must show that these combinations never contribute an answer.

These challenges motivate five research questions:
\begin{description}
\item[RQ1] Is it possible to prove correctness of a whole compiler
  using denotational semantics, i.e., from a higher-order language
  with general recursion down to an assembly language?
\item[RQ2] Does the compositionality and equational reasoning afforded
  by denotational semantics yield concise correctness proofs for some
  compiler passes?
\item[RQ3] Can equational reasoning prove all the passes of the whole compiler correct?
\item[RQ4] How does the denotational approach, with a graph model,
  compare overall with operational approaches to proving correctness
  of a whole compiler?
\item[RQ5] How does using Scott domains instead of a graph model affect the proof?
\end{description}

We answer RQ1 affirmatively. The final missing link is a new
denotational result: closure conversion both preserves and reflects
divergence for a higher-order language with general recursion. Our
semantics is a graph model: a program's denotation is a set of
inductively defined \emph{graph elements}. The key to the reflection
direction is a new kind of relation between denotations, which we call
an \emph{approximant logical relation}. Relating one target graph
element to one source graph element fails because a target call takes
the code and environment of a closure apart, from different pairs.
Relating whole denotations on both sides instead leaves the function
case, which uses the relation in negative position, with nothing to
recurse on. Our key insight is that the target side should be finite
and the source side should not: we relate a finite set of target graph
elements (a finite approximation), which contains both halves of each
call it describes, to the whole source denotation, and define the
relation by recursion on the depth of the elements in the finite set.
This definition is well founded without recursion on types or an index
that counts steps of computation. To our knowledge, this is the first relation between two denotational semantics indexed by finite approximations of one side only.

We use this closure-conversion result in the correctness proof of a
ten-pass compiler from a call-by-value $\lambda$-calculus with
iso-recursive types, which we call \iswim, to a typed assembly
language.  Recursive types let us write the call-by-value fixed-point
combinator, so \iswim\ has general recursion and admits
divergence. The compiler first applies a source-to-source optimizer
modeled on the cp0 pass of Chez Scheme \citep{Waddell:1997fk}, then
performs closure conversion in four passes, and finally uses five
passes to make functions global, remove complex operands, lift locals,
make control flow explicit, and select instructions. Every language in
the compiler has a denotational semantics. We prove most passes correct by an equation between the denotations before and after the
pass. RQ3 nevertheless has a negative answer. The pass that lowers
closures to code and environment pairs, which we call \pass{delay},
does not yield to equational reasoning; its reflection proof uses the
approximant logical relation discussed above.

The whole-compiler correctness theorem states that the source and
target denotations contain the same constants and are nonempty
together. We also prove that the denotational semantics of
\iswim\ and of the assembly language are adequate with respect to
the interpreters for those languages. Our correctness theorem is therefore equivalent to the usual operational one.  We mechanize all of these results in Agda.

In a graph model, each graph element is a finite piece of evidence
about a program's behavior, the meaning of a function is a set of
input--output entries, and a program that diverges produces no
evidence, so its meaning is the empty set
\citep{Engeler:1981aa,Plotkin:1993ab,Scott:1976lq}. We chose a graph
model because it is elementary: a denotation is a set of inductively
defined graph elements, so mechanizing the model takes a fraction of
the size of traditional domain theory (Section~\ref{sec:graph-models}).

The closest prior denotational proofs each stop short of this
combination of closure conversion, general recursion, and semantic
reflection. \citet{Chlipala:2007fk} proved correct a compiler from the
simply typed $\lambda$-calculus to assembly, including closure
conversion.  However, the simply typed $\lambda$-calculus has no
recursion: every program terminates, so there is no divergence to
preserve. For a language with recursive
functions, \citet{Nielsen:2000aa} used a domain-theoretic semantics to
prove that defunctionalization, a close cousin of closure conversion,
preserves the meaning of terminating programs. His type-indexed
relation and fixed-point induction establish semantic preservation but
say nothing in the other direction. Nielsen leaves that direction for
later: ``Eventually, we want to prove full correctness, i.e., semantic
equivalence of the two programs.''
\citet{Banerjee:2001aa} proved both directions, but gave an operational
semantics to the source language and a denotational semantics only to
the first-order target. They report that they ``know of no other proofs
of correctness (that is, both directions) for ordinary or CFA-based
defunctionalization in the presence of recursion.''

Other denotational compiler proofs for source languages that admit
divergence avoid closure conversion. Some concern compilers for first-order languages. \citet{Polak:1981aa} considers a subset of Pascal,
\citet{Xia:2019aa} use interaction trees for a compiler from an
imperative language to assembly, and \citet{Cheng:2026aa} use sets of
behaviors for the front end of CompCert. Others concern compilers whose target languages support closures directly, such as those of \citet{Clinger:1984aa}, Guttman, Ramsdell, and Wand \citeyearpar{Guttman:1995aa}, and \citet{Benton:2009aa}.

Operational proofs handle closure conversion with recursion,
with simulations (CompCert \citep{Leroy:2009aa}), clocked big-step
semantics (CakeML \citep{Kumar:2014aa}), or step-indexed logical
relations (CertiCoq \citep{Paraskevopoulou:2019aa}). When
\citet{Chlipala:2010aa} built a compiler for an untyped language with
general recursion, he switched to operational semantics, explaining
that the approach of his 2007 compiler ``cannot be applied directly to
Turing-complete programming languages.'' We know of no prior denotational proof of closure conversion for a language with general recursion that both preserves and reflects divergence.

Finally, to answer RQ2, RQ4, and RQ5, which depend on comparing the
graph-model proof with other styles, we prove the same compiler
correct four more times: with abstract machines and simulations, as in CompCert; with clocked interpreters and value relations, as in CakeML; with standard reduction semantics and simulations; and, denotationally, with Scott domains.  Each development covers the ten-pass pipeline and proves an
analogous correctness property in its own semantics. Earlier comparisons of semantic styles for compiler proofs cover a
single phase or pass \citep{Owens:2016aa,Kahn:2025aa}; ours is, to our
knowledge, the first on a compiler for a higher-order language down to
assembly that includes a denotational style.

The comparison answers RQ2 affirmatively and explains, pass by pass,
the mixed answer to RQ4. Where a pass keeps the representation of
values, equational reasoning is concise: the graph-model proof of the
source optimizer, \pass{simplify}, takes 349 lines against 508 to 697
for the operational proofs (Section~\ref{sec:equational}). Where a pass
changes the representation of closures, the relation between
denotations makes the proof larger, which quantifies the negative
answer to RQ3: the proof of \pass{delay} takes 450 lines against 35 to
126. The two effects nearly cancel. Counting each proof against its
own semantics, the graph-model development ranks second of the five,
behind clocked interpreters, and third once the language-independent
infrastructure is counted.
For RQ5, the Scott-domain proof is 1.4 times as large as the
graph-model proof. The main reason is that Scott values are infinite:
the relation for \pass{delay} cannot recurse on them, and because the
method of \citet{Pitts:1996aa} does not apply directly, we built it
stage by stage, as \citet{Reynolds:1974aa} did.
