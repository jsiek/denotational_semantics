\section{Introduction}
\label{sec:intro}

This paper proves a compiler, including closure conversion, correct
with respect to denotational semantics, and it compares these proofs,
pass by pass, with proofs of correctness with respect to operational
semantics. We give the first denotational proofs that closure
conversion both preserves and reflects the meaning of programs,
divergence included, for a Turing-complete language, one proof in a
graph model and one in Scott domains. We extend both proofs to an
eight-pass compiler for the FPC language \citep{Plotkin:1985aa} that
targets a typed low-level intermediate language. We then compare these
proofs to three more proofs of correctness for the same compiler, each
with respect an operational semantics: clocked interpreters, abstract
machines, and reduction semantics. For every pass, the smallest proof
is either the graph-model proof or the interpreter proof, and we
identify the properties of a pass that favor each of the two
(Section~\ref{sec:evaluation}).  We mechanize all of our results in
Agda and provide the development as supplementary material.
Section~\ref{sec:compiler} presents the compiler,
Section~\ref{sec:graph-models} the graph model, and
Section~\ref{sec:compiler-proof} the proofs.
Section~\ref{sec:evaluation} compares the five proofs,
Section~\ref{sec:related} discusses related work, and
Section~\ref{sec:conclusion} concludes. The appendices define the
semantics of every language and define every pass in the compiler.

A compiler is correct with respect to a semantics of its source and
target languages, and the style of that semantics shapes the
proof. \citet{Leroy:2009aa} proves CompCert correct with respect to
small-step semantics, using simulations, and \citet{Kumar:2014aa}
prove CakeML correct with respect to clocked interpreters (also called
functional big-step semantics \citep{Owens:2016aa}), using induction
on evaluation. Operational semantics are neither compositional nor
extensional. A small-step semantics
yields behavior as a by-product of transitions, and in a big-step
semantics a closure contains syntax \citep{Kahn:1987aa}. Proofs about operational semantics therefore
often need simulations \citep{Milner:1995aa} or logical relations
\citep{Plotkin:1973fk,Statman:1985aa}, which grow daunting for
realistic languages \citep{Ahmed:2009aa,Hur:2011aa}.

Denotational semantics offers a different recipe. A denotational
semantics is compositional, defined by structural recursion on syntax
\citep{Winskel:1993uq}, and extensional, specifying only the
observable behavior of programs \citep{Schmidt:2003aa}. A compiler
pass is correct when the meaning of a program before the pass equals
its meaning afterward, and compositionality lets the proof proceed by
structural induction and equational reasoning. Early compiler proofs
followed this recipe \citep{Polak:1981aa,Clinger:1984aa}. Mechanizations
of the standard domain-theoretic models are large
\citep{Benton:2009ab,Dockins:2014aa}. In the graph models of the
$\lambda$-calculus
\citep{Engeler:1981aa,Plotkin:1993ab,Scott:1976lq,Coppo:1979aa,Barendregt:2013aa},
a function denotes a set of finite input--output tables. In our
development, the infrastructure for the
graph model takes 1,544 lines of Agda, against 7,834 for Scott domains
(Table~\ref{tab:infra}). We ask whether denotational semantics, and
graph models in particular, extend to a compiler for a higher-order
language, and how the proofs compare in size with operational ones.

However, the recipe runs into \emph{closure conversion}, the pass by
which every compiler for a language with lexically scoped functions
replaces each function with a pair of code and the values of its free
variables, and each call with code that takes the pair apart. Closure
conversion turns functions into data, so its correctness proof must
relate two representations of a function. To date, every proof of
compiler correctness with respect to a denotational semantics stops
short of closure conversion for a Turing-complete language, each in
its own way. \citet{Chlipala:2007fk} proved correct a compiler from
the simply typed $\lambda$-calculus to assembly, including closure
conversion, but every program of that language terminates, so there is
no divergence to preserve.  \citet{Nielsen:2000aa} used a
domain-theoretic semantics to prove that defunctionalization, a close
cousin of closure conversion, preserves the meaning of programs with
recursive functions, and left the other direction for later, writing
``Eventually, we want to prove full correctness, i.e., semantic
equivalence of the two programs.''  \citet{Banerjee:2001aa} proved
both directions, but gave the source language an operational
semantics. They report that they ``know of no other proofs of
correctness (that is, both directions) for ordinary or CFA-based
defunctionalization in the presence of recursion.'' Other denotational
proofs avoid closure conversion, because their source language is
first-order \citep{Polak:1981aa,Xia:2019aa,Cheng:2026aa} or their
target language has closures
\citep{Clinger:1984aa,Benton:2009aa}. When \citet{Chlipala:2010aa}
proved correct a compiler for a language with recursion, he switched
to operational semantics, explaining that the denotational approach of
his 2007 compiler ``cannot be applied directly to Turing-complete
programming languages.''

A correct compiler must both preserve and reflect the behavior of
programs. \emph{Semantic preservation} says that if the source program
produces an output, the target program produces the same output, and
\emph{semantic reflection} says that if the target program produces an
output, the source program produces the same output. By
contraposition, reflection guarantees that a diverging source program
compiles to a diverging target program. Reflection is where
closure conversion resists a denotational proof, because the
relation between source functions and target closures refers to itself
in negative position, and the domain of meanings is recursive. In a
graph model there is a further problem. The meaning of a function's
code describes its behavior on every environment, not just the
environment with which the compiled program pairs it. The target
denotation therefore contains code--environment combinations that
correspond to no source function, and a reflection proof must show
that these combinations never contribute an answer.

These observations lead to three research questions:
\begin{description}
\item[RQ1] Can we prove a compiler for a Turing-complete language
  correct through closure conversion, in both directions, with respect
  to a denotational semantics?
\item[RQ2] How do the sizes of mechanized correctness proofs of one
  compiler compare across five semantic styles, two denotational and
  three operational, pass by pass and overall?
\item[RQ3] Which properties of a pass determine the size of
  its correctness proof in each style?
\end{description}

We answer RQ1 affirmatively, in two models. Our first model is a graph
model, in which a program denotes a set of inductively defined
\emph{graph elements}. Each element is a
finite piece of evidence about the program's behavior, the meaning of
a function is a set of input--output entries, and a program that
diverges produces no evidence, so its meaning is the empty set. For
reflection we introduce a new kind of relation between denotations,
the \emph{approximant logical relation}. Our key insight is to relate
a finite set of target graph elements (a finite approximation) to a
possibly infinite source denotation, and to define the relation by
recursion on the depth of the elements in the finite set
(Section~\ref{sec:approx-lr}). Our second model uses Scott domains, in
which a program denotes an element of a universal domain of tagged
values and divergence is the least element. There we define the
relation by recursion on the stages of the bilimit that constructs the
domain, as \citet{Reynolds:1974aa} did to relate direct and
continuation semantics. At each stage, the relation relates an
approximation of one value to the whole other value
(Section~\ref{sec:scott-delay}).

We use these results in two correctness proofs of an eight-pass
compiler. Its source language is \fpc, the call-by-value
$\lambda$-calculus with sums, products, and iso-recursive types of
\citet{Plotkin:1985aa}, extended with integers. Recursive types let us
write the call-by-value fixed-point combinator, so \fpc\ has general
recursion and admits divergence. The compiler applies a source optimizer modeled on the cp0
pass of Chez Scheme \citep{Waddell:1997fk}, three closure-conversion
passes, and four back-end passes that produce \instr, a typed
low-level intermediate language. Every language in
the compiler has a semantics in each model. For seven of the eight
passes, the proof in either model is an equation between the meanings
before and after the pass. The exception is the pass that separates
the code of each closure from its environment, \pass{split closure},
whose reflection proof uses the approximant logical relation in the
graph model and the stage relation in Scott domains. The
whole-compiler theorem says that the source and target denotations
contain the same constants and are nonempty together. We also prove
that the denotational semantics of \fpc\ and of \instr\ are adequate
with respect to their interpreters, which makes our theorem equivalent
to the usual operational one.

To answer RQ2 and RQ3, we compare the two denotational proofs with
proofs of correctness of the same compiler with respect to three
operational semantics, each proved with the technique usual for its
style: clocked interpreters with relations on values, abstract
machines with simulations, and reduction semantics with simulations.
Earlier work compares or combines semantic styles for a single phase
or pass of a compiler \citep{Owens:2016aa,Kahn:2025aa,Knothe:2026aa};
ours is the
first on a whole compiler for a higher-order language. We leave other
styles to future work, among them synthetic domain theory
\citep{Rosolini:1986aa,Hyland:1991aa} and its guarded variant
\citep{Birkedal:2011aa,Mogelberg:2016aa}, categorical semantics
\citep{Fiore:1994aa}, coinductive and pretty-big-step semantics
\citep{Leroy:2009rc,Chargueraud:2013aa}, the partiality monad
\citep{Danielsson:2012aa}, game semantics \citep{Hyland:2000ve}, and
action semantics \citep{Mosses:1996rp}. We did not use interaction
trees \citep{Xia:2019aa}, because a direct denotation of a
higher-order function as an interaction tree needs a type of values
that occurs negatively in its own definition, and the positivity
checks of Coq and Agda reject such a definition. Guarded interaction trees
\citep{Frumin:2024aa} lift this restriction by moving to guarded type
theory.

No style gives the smallest proof for every pass (RQ2). Counting each
proof together with the semantics of its languages, the clocked interpreters give the
smallest proof, at 1,504 lines of Agda, and the graph model gives the
second smallest, at 1,808, ahead of abstract machines, Scott domains, and
reduction semantics. If we also count the language-independent
infrastructure, the graph model ranks third and Scott domains fifth.
Two factors largely explain the sizes (RQ3). The size of a
denotational proof tends to depend most on whether the pass preserves the meaning of a program
exactly. The source optimizer, \pass{simplify}, does, and its
graph-model and Scott-domain proofs take 349 and 411 lines, against
508 to 697 for the operational proofs (Section~\ref{sec:equational}).
\pass{split closure} does not, and its proofs take 450 and 723 lines,
against 35 to 126. The size of an operational proof tends to depend
instead on how closely the run of the target follows the run of the source.
The runs correspond closely for \pass{split closure}, which is why its
operational proofs are small, and differ more for \pass{simplify},
which inlines functions. Without \pass{split closure}, the graph-model
proof would be the smallest of the five. The Scott-domain proof is 1.4
times as large as the graph-model proof, and \pass{split closure} accounts for 40\% of the
difference (Section~\ref{sec:evaluation}).
