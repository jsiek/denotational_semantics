Our compiler translates \iswim, a call-by-value $\lambda$-calculus
with recursive types, to X86$\mu$, a typed assembly language, in ten
passes through seven intermediate languages:

The grammars for all the languages are presented in
Figure~\ref{fig:grammars}, and their typing rules in
Appendix~\ref{app:types}.\footnote{Every language is intrinsically
typed in our Agda development, so every term is well typed by
construction and no pass needs a precondition about scoping or
typing.}  Every language also has a semantics in the graph model of
Section~\ref{sec:graph-models}, given in full in
Appendix~\ref{app:languages}, and
every pass except delay preserves the meaning of a program exactly.

\paragraph{The source language}
\iswim\ has integers, $n$-ary tuples, binary sums, the primitives
$\kw{sub}$ and $\kw{eq}$, and iso-recursive types. Most of its forms
are standard. The primitive $\kw{eq}$ returns $\kw{inl}\;\langle\rangle$
for true and $\kw{inr}\;\langle\rangle$ for false, so $\kw{case}$ serves
as the conditional. A recursive type $\mu X.\, A$ is isomorphic to its
unfolding $A[\mu X.\, A / X]$, and the two coercions of this
isomorphism are explicit: $\kw{fold}$ turns a term of the unfolding
into a term of the recursive type, and $\kw{unfold}$ turns it back.
Neither does anything at run time:
\[
  \frac{\Gamma \vdash M : A[\mu X.\, A / X]}{\Gamma \vdash \kw{fold}\;M : \mu X.\, A}
  \qquad
  \frac{\Gamma \vdash M : \mu X.\, A}{\Gamma \vdash \kw{unfold}\;M : A[\mu X.\, A / X]}
\]
The other typing rules are standard (Appendix~\ref{app:types}). \iswim\ has no recursion operator.
Instead, recursive types make self-application typable, so the
call-by-value fixed-point combinator can be written directly:
\[
  \mathit{fix} = \lambda f.\, g\;(\kw{fold}\;g)
  \quad\text{where}\quad
  g = \lambda x.\, f\;(\lambda v.\, (\kw{unfold}\;x)\;x\;v)
\]
with $x : \mu X.\, X \rightarrow (\kw{Int} \rightarrow \kw{Int})$.

\paragraph{The optimizer}
The first pass, simplify, is a simplified version of the source
optimizer cp0 of Chez Scheme \citep{Waddell:1997fk}. It propagates
known values, folds primitives on known constants, reduces a
$\kw{case}$, projection, or $\kw{unfold}$ of a known value, and inlines
calls to small known functions.

\paragraph{Closure conversion}
The next four passes perform closure conversion. Enclose turns each
$\lambda$-abstraction into a closure $\kw{clos}\;N\;\vec{M}$ of Clos,
whose code $N$ is closed: its free variables are a name $x_i$ for each
captured value $M_i$ and the parameter $y$. Enclose captures every
variable in scope, and optimize then drops the captured values that the
code does not use. Concretize stores the captured values of a closure
in a single environment tuple, so the code of an EnvClos closure has
two free variables, the environment $e$ and the parameter $y$, and
reads $x_i$ as $\kw{get}_i\,e$. Delay then separates a closure into its
code and its environment (Section~\ref{sec:approx-lr}). In FlatClos,
$\kw{code}\;N$ is closed code of type $\kw{code}(\Delta; A \rightarrow
C)$, which expects an environment of type $\kw{tup}(\Delta)$ and an
argument of type $A$. The form $\kw{pack}\;L\;M$ builds a closure from
code $L$ and an environment $M$ of the same $\Delta$. Its type,
$A \rightarrow C$, hides $\Delta$, as in the existential type
$\exists \Delta.\, \kw{code}(\Delta; A \rightarrow C) \times
\kw{tup}(\Delta)$ of typed closure conversion \citep{Minamide:1996ys},
so closures with different environments have the same type. The form
$\kw{callc}\;L\;M$ opens the closure $L$ and calls its code with its
environment and the argument $M$.
\[
  \frac{e : \kw{tup}(\Delta),\, y : A \vdash N : C}
       {\Gamma \vdash \kw{code}\;N : \kw{code}(\Delta; A \rightarrow C)}
  \qquad
  \frac{\Gamma \vdash L : \kw{code}(\Delta; A \rightarrow C)
        \quad \Gamma \vdash M : \kw{tup}(\Delta)}
       {\Gamma \vdash \kw{pack}\;L\;M : A \rightarrow C}
\]
\[
  \frac{\Gamma \vdash L : A \rightarrow C \quad \Gamma \vdash M : A}
       {\Gamma \vdash \kw{callc}\;L\;M : C}
\]
Since $\kw{callc}$ is the only way to open a closure and works for
every $\Delta$, no run-time check is needed.

\paragraph{The back end}

Globalize turns the code of every function into a global definition
$d_k$, and each occurrence of the code into a reference $f_k$ to it, so
a GlobalFun program is a list of definitions and a main term. Remove
complex operands binds each operand that is not an atom to a variable
with $\kw{let}$, so the operands of every operation in Mon are atoms.
Lift locals gives each variable a fixed location in the function's
stack frame, called a \emph{slot}, numbered by how many variables are
bound before it. We keep writing $x$ and $y$ for these variables, but
from Imp on they stand for slots, and each $\kw{let}$ becomes an
assignment to the next slot. There is no register allocation: every
local variable lives in its slot. Explicate control
turns the nested $\kw{case}$s of Imp into a control-flow graph of
blocks that end in a $\kw{return}$, a $\kw{goto}$, or a $\kw{case}$
that jumps to one of two blocks.

Finally, select instructions produces X86$\mu$, a typed assembly
language in the style of TAL \citep{Morrisett:1999fk} with the
registers $\kw{rax}$, $\kw{rdi}$, and $\kw{rsi}$, a frame of slots,
and an abstract heap. The registers are used to stage arithmetic
and calls. The instruction $\kw{alloc}$ allocates a closure, a tuple,
or an injection. A call first opens the closure in a slot $x$:
$\kw{load}\;\kw{fst}\;x, \%r$ loads its code, and
$\kw{load}\;\kw{snd}\;x, \%r$ loads its environment. Then $\kw{callq}$
calls the code with the environment in $\kw{rdi}$ and the argument in
$\kw{rsi}$, and the result arrives in $\kw{rax}$. The type system
tracks which closure is open, so that a call never combines the code
of one closure with the environment of another. A $\kw{case}$ is a
single pseudo-instruction that tests the tag of an injection, writes
its payload to a slot, and jumps to one of two blocks; it stands for a
test, a load, and a conditional jump. The coercions $\kw{fold}$ and
$\kw{unfold}$ survive to X86$\mu$ as annotations on operands,
$\kw{fold}\;a$ and $\kw{unfold}\;a$, which do nothing at run time.
